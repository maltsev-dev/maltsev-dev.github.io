# The stylesheet pass — what the dead-code sweep is and how to run it

The design contract is `docs/superpowers/specs/2026-11-16-site-simplification-design.md`.
Section 6 is the brief for this pass; the rest of the contract still applies
(especially "the contract" and "what does not change").

## What is already in place — do not revert

- `src/styles/global.css`, `:root`:
  `--measure-prose: 68ch;` and `--measure-doc: 46rem;`.
- `src/styles/tty.css`, `.tty-fit`:
  `width: var(--w, fit-content); max-width: 100%; margin-inline: 0;`

## The two tokens and where they go

- `--measure-prose` — the measure of a paragraph of prose **inside a window**.
  Apply it to `.prose` (currently `max-width: 68ch`) and `.prose.post-prose`
  (currently `max-width: 64ch`), and to any other rule that caps a run of
  prose inside a window with a bare `ch` value.
- `--measure-doc` — the default width of a window that holds prose. The
  prose page (`/about/`) sets `--w: var(--measure-doc)` on its page wrapper,
  so its windows are one 46rem column.

## The dead-code sweep

The list of what is dead cannot be read off the CSS — it has to be measured
against the built site. `tools/dead-classes.mjs` does that:

```
node tools/dead-classes.mjs <build-dir>
```

It prints, per stylesheet, the classes that the stylesheets style and that
nothing in the built site ever names. It also covers the classes the scripts
create at runtime (`classList.add`, `className =`), so a class that only
exists once a script runs is not reported as dead.

**The measurement decides, not the list in the contract.** The contract names
systems that are dead — `.skill-pyramid` / `.skill-chip` / `.skill-card`,
`.post-nav*`, `.post-related*`, `.tl-*`, `.big-block*`, `.resources*`,
`.pipe-*`, `.field*`, `.kv`, `.sticky-head`, `.rule-progress`, `.card*`,
`.os-panel` — but some of those names are also live in a different file (the
home page uses `.card-meta`). What goes is what the measurement says goes: a
class the stylesheets style and no built page and no script ever names.

Two things to be careful about:

1. **A rule that targets a dead class may also carry a live one.** Delete the
   dead half of the selector, not the whole rule. `.ls-row.is-dir .ls-mode` is
   live because `is-dir` is live.
2. **A class can be dead in one stylesheet and live in another.** `.post-cta`
   is dead in `global.css` — the markup uses `.post-cta-mail`, a different
   class — but `.post-cta-mail` is live and stays.

Run the tool again after the sweep: the count of dead classes should fall to
zero, and no live class should have been taken with it.

## The skill tree

The skill tree replaced the pyramid and the CSS for the pyramid stayed.
`.skill-tree`, `.skill-name` and `.skill-facts` have **no styles at all**
today, so the tree and the counts beside each name run together as one grey
line. The tree needs real styles:

- `.skill-tree` — the container.
- `.skill-tier` — one tier. The pyramid's rules (centred, tapered to a
  percentage width, bordered slab) have to go: a tree is not a pyramid and
  the taper is the pyramid's silhouette, not the tree's.
- `.skill-tier-name` / `.skill-tier-dir` / `.skill-tier-count` — the tier
  label and the count of skills in it.
- `.skill-tree-list` — the leaves. It is also a `.tree`, so the box-drawing
  connectors from `tty.css` apply; the tree's own rules should let it hang
  from one place, not be centred under its label.
- `.skill-name` — the name of the skill.
- `.skill-facts` — the counts beside it ("3 jobs · 2 certs · 1 project").
  These are the numbers the pyramid's hover card used to hide behind a
  pointer. They must read as metadata, not as part of the name.

`src/pages/experience.astro` carries two page-scoped rules that style the
tree (`.skill-tree .skill-tier { align-items: flex-start; }` and
`.skill-tree .skill-tree-list { margin-left: 1.6rem; }`). They belong with
the rest of the tree's styling, in `skills.css` — remove them from the page
and put the tree's appearance in one place.

## The contrast fix

`.stack-zone.is-hot` sets `color: var(--fort)` on a 26% accent tint. The
figure's art is `--encre` (see `.stack-art`), so the hot zone was dimmer than
the drawing around it — and it fails the AA floor:

| theme | hot background | `--fort` on it | `--encre` on it | `--creme` on it |
|---|---|---:|---:|---:|
| phosphore | `#4c270a` | 5.50:1 | 7.16:1 | 10.29:1 |
| acidule | `#004336` | 4.43:1 ✗ | 8.52:1 | 10.03:1 |
| pierre | `#e0c2b1` | 3.87:1 ✗ | 8.87:1 | 10.91:1 |

The hot zone takes the brightest text colour instead — `--creme`, which is
what the token is for ("the brightest text: headings, the cursor, the thing
the eye lands on"). The figure is a lit panel; the stage the reader has
selected is the lit part of it.

Put the measured numbers in the comment, the way the rest of the stylesheet
documents its contrast.

## What does not change

- The three themes and every token in them. No hex value moves.
- The typefaces.
- The terminal vocabulary: windows, listings, prompts, lamps, the ASCII figure,
  the block-letter wordmark.
- Nothing gets a new typeface, a new colour or a new animation.
